# 0005. 请求期贴的字冻结不改

状态：采用

## 背景

桥在每次请求发出前，会给历史里的旧消息现贴一些字（比如桌面打字的抬头、游戏旧局面的标签），也会按固定的写法认出某些消息。这些字不存在会话日志里，每次请求现算。

压缩代理按消息内容给每条消息编号。请求期贴的字一改，历史里所有这类消息的内容就变了，编号全换：

- 缓存整段失效一次，下一次请求重付全价；
- 旧的压缩块是按旧编号盖住这些消息的，换了编号就盖不住了，原文重新摊回请求里。

## 决定

- 桥在请求期贴的字、认消息用的写法，一旦上线就冻结，不改。
- 要改说法，只改落盘时写的标签（只影响新消息），或者改系统提示（不影响旧消息的编号）。
- 换桥之前，拿同一份假历史在旧桥和新桥上各过一遍请求期改写，旧消息必须逐字相同；不同就不换。
- 桥不要在系统提示后面再加系统角色的消息。

## 后果

- 缓存和旧块稳定。
- 一些早期的措辞即使不理想也只能留着；新旧两种写法要并存认。
- 每次换桥多一步比对（请求对照工具第二批发）。
- 有些改写本来就随状态变（比如开关打开时才走的那几条），要单独列出来，知道它们会动编号。
