# 0004. 身份走配置，读不到就当没有主人

状态：采用

## 背景

「谁是主人」「主人的私聊是哪个」「她叫什么」「证据账在哪」，早先散写在各个插件的代码里：桥一份，账本插件一份，压缩代理一份。改一处漏一处，几份对不上时，门会判错。

公开代码也不能带任何个人的号码、称呼和路径。

## 决定

- 一份共用的身份配置（`packages/config` 读，格式见它的 `SCHEMA.md`），写：主人在各个渠道的号、主人的称呼、陪伴体的名字和号、她可以主动开口的聊天、主会话怎么认、证据账根。
- 桥、插件、代理都从这一份读，不各写各的。第一批先有读配置的包；桥第二批接上，到时按需要加键（比如维护助手的渠道），加键要升格式版本。
- 认主人要两条都对：信封上的作者记号是主人，而且聊天地址是主人自己的私聊（由配置里主人的号算出）。
- 哪几类来源算「只有主人和她」，不写在身份配置里，写在门的开关文件（`gate.json` 的 `classes`）里。
- **配置读不到、读坏了，就当没有主人**：所有来话都按别人的话算，所有轮都按 `gate` 判。不猜。
- 给她看的文字里，主人的称呼一律从配置取。

## 后果

- 公开代码里没有个人值；换一个人用，只换配置。
- 配置坏了，主人那几轮也会被当成群挡：这是有意的，出错的方向是收紧。
- 配置是一个新的单点：要备份，改了要重启或现读（看各组件怎么读）。
- 老的硬写的值要逐处搬进配置，搬的时候每处都要有测试核对「搬前搬后判得一样」。
