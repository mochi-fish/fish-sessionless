# 0007. heard 的写入失败即关

状态：采用

## 背景

dsh-fish 会把用户本人的话记成「听到过」（heard），她用回想工具翻得到。但经桥送进来的主人的话，dsh-fish 当成插件消息丢掉，从来不进她的事件流。补上它（P0.5），她就能翻到主人说过的话。

写进事件流的删不掉。而回想工具在群里一用，就会把主人私聊的原话带进群那一轮。所以「什么时候开始写」不能出错，开关坏了也不能变成「写」。

## 决定

- 开关是证据账根下的一个文件，她和帮手碰不到：
  - 文件不在：只数不写；
  - 明确写着「写」：才写；
  - 读错、认不出、账本根不在：不写。
- 桥只在工具的门处于 `enforce` 时才真写；门在 `audit` 或 `off` 时一律只数。
- 真写过一次以后，留一个只升不降的记号；有记号时，回想工具在群、来客、维护助手那几轮永久挡，不看门的开关档。
- 开始真写要主人点头。
- 写之前用 dsh-fish 自己的函数洗正文；信封上的每一段都必须是主人。

## 后果

- 开关坏了、文件丢了、账本没了，结果都是「不写」：不会意外把主人的话写进去。
- 门和 heard 要成对回退：heard 真写过以后，门不能单独退回只记。
- 回想工具在群里永久少了一样本事。
- 写的逻辑靠 dsh-fish 内部函数的形状，dsh-fish 每次升级都要拿真包重跑测试。
