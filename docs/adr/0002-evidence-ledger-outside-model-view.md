# 0002. 证据账放在模型和工具碰不到的地方

状态：采用

## 背景

后面的每一道门都要回答「这条材料能不能给这一轮的人看」。答案要可信：不能交给模型猜，也不能被模型或外人改。

可选的地方有：写进她的会话日志（作为元数据）、写进压缩代理的账本、单开一本账。

写进会话日志，模型看得到，也删不掉；写进代理的账本，只覆盖经过代理的那一段，宿主落盘的事看不到；而且她和替她办事的帮手如果读得到、写得进这本账，群友就可以借她改账、或者读到账里的来历。

## 决定

- 单开一本只追加的证据账，放在家目录下一个独立的目录里。
- 三个写者（桥、fish-ledger 插件、压缩代理）各写各的子目录，一个文件只有一个写者。
- 账里不存原文，只存编号、假名、带盐的 HMAC、字数、计数、模型名。号码一律换成假名。
- 这个目录对她和替她办事的帮手关上：她的文件工具、搜索工具、帮手的命令都挡掉。
- 记账失败不影响她这一轮；记账不改她看到的任何东西，也不改发给提供方的字节。
- 工具的门的开关也放在这个目录里。

## 后果

- 来历可信：她和群友改不了。
- 账里没有原文，泄了也只是编号和哈希；但要配盐，盐丢了新旧就连不上。
- 多了一个要维护的目录和三份写者逻辑（序号、分卷、半行隔离、锁）。
- 对账要离线工具做，进程里不做。
- 她看不到自己的账。如果以后要让她看，要另做一份只读、按读者过滤的视图。
