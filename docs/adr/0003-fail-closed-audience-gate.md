# 0003. 群和来客那几轮，工具的门失败即关

状态：采用

## 背景

在群里，她一用「展开旧块」「翻事件流」「读便条」这类工具，私聊的内容就会回到下一次请求。要挡，就要判断「这一轮是谁在听」和「这个工具的结果会带出什么」。

这两件事都可能判错，门本身也可能坏（插件没加载、开关读不出、判定代码出错）。错的方向只有两种：误放（泄露）或误挡（她少一样本事）。

对群和来客，误放的后果收不回来；对主人，误挡会让主人觉得「她变笨了」，而且主人那几轮本来就什么都能看。

## 决定

- 分三类轮：`open`（主人、她自己）照旧放；`gate`（群、来客、认不出的）按表挡；`watch`（维护助手）只记不挡。
- `gate` 类：表里没有的工具挡；读者算不出按最严；开关读不出线上按 `enforce`；插件没给判定，桥按同一张表兜底；判定代码出错就挡。
- `open` 类：门不加任何限制；只有能确定是主人的轮才算 `open`。
- 挡下时回一句固定的照实话，不说「没找到」。
- 先 `audit`（只记不挡）跑一段时间，看过数据再切 `enforce`。
- 主人那一轮一旦被误挡，自动把「认不清」那几种退回只记，群和来客照挡。

## 后果

- 群和来客那几轮安全优先：她在那里少了回想、读便条、读文件这些本事。
- 主人那几轮不受影响；误挡有专门的计数和自动退回。
- 照实话会让群友知道「有只给主人的那几轮」（泄机制，不泄内容）。
- 门只管「用了工具以后」；请求本身的历史要到 P2 才按受众拼。
