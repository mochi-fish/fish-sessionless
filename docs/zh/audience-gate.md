# 受众和工具的门

光把请求拼干净还不够。她一用工具，旧事就可能从工具结果回到下一次请求。所以群和来客那几轮，能翻到过去的工具缺省挡住，只放行逐个核过的。这一步叫 P1，排在「按受众拼请求」（P2）之前。

判定代码在 `packages/audience`（纯函数），门挂在 `packages/fish-ledger`（DSH 插件）上，桥在自己的检查里兜底。

## 这一轮谁在听

这一轮的读者由信封定，不交给模型判断。

| 来话 | 这一轮的读者 |
|---|---|
| 主人的私聊、主人在桌面上打字 | 主人和她 |
| 某个群 | 这个群和她（拿不到成员名单，就把整个群当成一个人） |
| 来客的私聊 | 这位来客和她 |
| 她自己醒来、夜里那一轮 | 只有她 |

**怎么认出是主人的私聊**：两条都要对。信封上的作者记号是 a 或 x，而且聊天地址是主人自己的私聊（由配置里主人的号算出）。记号对、地址对不上，按来客算。配置读不到，就当没有主人：所有来话都按别人的话算。

### 一轮分三类

| 类 | 包括 | 门怎么做 |
|---|---|---|
| `open` | 主人的私聊和桌面、她自己起的轮、开关文件 `classes` 里标成 `open` 的来源 | 照旧放行 |
| `gate` | 群、来客私聊、游戏里的公屏、别人递来的便条、认不出来的 | 按表挡 |
| `watch` | 维护助手的渠道 | 照表算，只记不挡 |

一轮里混进了不同的人（比如她忙的时候，群里的话和主人的话排进了同一轮），按交集算：**工具结果的读者必须盖住这一轮在场的所有人**，最严的说了算。主人在群里叫她，这一轮也按群算。

## 门挂在哪

- **插件**：fish-ledger 挂在宿主的「工具执行前」口子上，排在最外层，工具真正执行之前就判。
  - 只回「拒绝」，不回「问用户」。在「全放行、不审批」的权限设置下，「问用户」会落成一句「用户拒绝了这个工具」，还往会话里记一对审批记录。那是假话。
  - 挡下的调用也回一个结果，不删掉：模型那边「调用」和「结果」必须成对。
- **桥兜底**：宿主只在「执行前」全放行以后，才跑各插件的检查。所以插件挡下的，桥看不到；插件没给某次调用留判定（没加载、出错、被别的插件绕过）时，桥按同一张表、同一个开关自己判。
- **不靠心跳决定挡不挡。** 心跳一分钟一次，按心跳兜底会漏掉中间那一段。心跳只用来报状态。
- **两边用同一个函数判读者**：插件和桥各自把同一条会话事件流喂给同一个归约函数，得到同一张轮次表。两边不一致，按严的，并计数。

## 判定次序

1. heard 已经真写过、工具是翻她事件流的那个、这一轮不是 `open`：挡。不看开关。（理由见下面「heard 真写过以后」）
2. 这一轮是 `open`：放行，照样留一条判定。
3. 这个工具名她根本看不到：不管，由宿主照旧报「没有这个工具」。不然她会对一个不存在的工具读到「这一轮不开」，那也是假话。
4. 查表：先按全名，再按前缀。表里没有的：**挡**，只记名字和次数，人看过再决定加不加。
5. 表里写「放行」就放，写「挡」就挡，写「按参数」就先让里面的检查跑完，再看最后的参数判。
6. `watch` 类：照上面算，最后一律放行，「挡」记成「本该挡」。

开关文件里的 `allowTools`、`blockTools` 在查表之前生效，给人看过数据以后逐个调。`classes` 可以逐个改某一类来源归 `open`、`gate` 还是 `watch`；不写就用缺省的归法。

## 工具怎么归类

表按工具逐个写。下面是类别和理由。

**放行**

- 发话。目标必须在这一轮的读者里，是 P2 的出口核对。
- 压缩。P2 以后压的是这条受众链自己的。
- 写便条。只挡「读」的动作。
- 逐个核过的公开内容工具（看公开视频、画图、查梗这类）。
- 外部记忆库（Mem）的工具：每一轮都放行，读写都放。这是一个有代价的决定，见 [ADR 0006](../adr/0006-mem-tools-every-turn.md)。

**按参数判**

- 翻聊天记录：只许翻这个群或这位来客自己的。
- 读图、发图：只许这个聊天里出现过的图、这一轮给这个聊天画的图。
- 发表情包：只认表情包图库里的图。

**挡**

- 展开旧块、搜旧块、看块列表。块的标题和内容里可能有私聊。P2 以后只许查这条链自己的块，和主人批准过的「受众版」。
- 翻她自己的事件流。事件流只记得是群还是私聊，记不下是哪个群、和谁；她写下的话又按写的时候最严算。没有能安全放的，一律挡。
- 读便条、搜日记、读家目录和工作区的文件、读证据账。
- 改写文件。宿主会把她家目录里的说明文件读进以后的每一轮，外人借她写一个，就能给她下指令。
- 网页搜索、网页抓取。会把她写的字送到外面。做成开关，缺省关。
- 帮手、定时任务、以前画的图、听到的原话这类。
- 表里没有的。

## 挡下时回什么

一句固定的照实话。大意是：

> 这一下在这一轮不开（这一轮不只有{主人的称呼}和你），没有结果给你。没拿到不等于没有，别把这一下记成「查过、没有」。

`{主人的称呼}` 取配置里的称呼。为什么这样写：

- 不说「没找到」「不存在」。门造的结果会落进她的主日志，成为她生活史的一部分；写进摘要也不该变成假记忆。
- 不指她「换个时候再用」。那等于教她挪到没有门的那一轮去办。
- 代价：模型知道有一个它看不到的范围。她在群里原样转述的话，群友会知道「有只给主人的那几轮」。泄的是机制，不是内容。

日志里另带一个机器记号（模型看不到），证据账记一行「门造的结果」。

## 三档开关

开关是证据账根下的 `gate.json`：

```json
{"schema":1,"mode":"audit",
 "classes":{},
 "allowTools":[],"blockTools":[],"allowPaths":[],
 "autoAudit":"uncertain-only","rearm":null,"heardSticky":false}
```

| 档 | 做什么 | 她看到的 |
|---|---|---|
| `off` | 不判、不记（只有 heard 那一条照判） | 和没有门一样 |
| `audit` | 照判，但一律放行，「本该挡」记账、计数 | 和没有门一样 |
| `enforce` | 照判、照挡 | 群里翻不到旧事、看不到便条和日记 |

- **为什么放在证据账根**：那个目录已经对她和替她办事的帮手关上。放在她写得进去的地方，群友就能借她把门关掉。
- **每次调用现读**：看修改时间和大小，变了才重读。改了不用重启。
- **读不出来**（文件不在、坏的、版本不认识）：线上那份按 `enforce`；副本和测试按 `off`。单个键不对，那个键用默认值。
- **停记账不关门**：根下的 `off` 文件只停写账。关门只有 `mode: "off"`。
- 插件和桥读同一个文件。桥没有自己单独的开关。

## 先只记，再真挡

建议的顺序：

1. 先 `audit` 上线，只记哪些本该挡，一样都不挡。
2. 只记满一段时间（例如 72 小时，最少 24 小时）。看数：群和来客那几轮本该挡几次；主人那几轮会不会被误挡，必须是 0；「认不清」的每一种都说得清是哪个入口。
3. 告诉她，听她怎么说。
4. 主人看过以后，再切 `enforce`。

只记的时候记：工具名、这一轮的类别、表里哪一行、会不会挡、主人在不在场。**不记**正文、参数、路径、号码、群名。

## 主人那一轮被误挡

- **定义**：真挡了一次，这一轮有主人的话，两边的轮次表合起来又没有任何已知该挡的人，挡的原因只来自「认不清」「两边不一致」「表丢了」「判定代码出错」。
- **一出现就退回**：缺省只把「认不清」那几种退回只记，群和来客照挡（`autoAudit: "uncertain-only"`）。也可以选整个退回只记（`"all"`），但那样一次认不清就把已知的漏口全放开，出错的方向是放。
- 退回会写一行操作记录。要恢复，人看过以后写 `rearm` 的时刻，不用重启。
- **不算误挡的**：主人在群里叫她、主人的话和群混在一轮。这是按设计挡，单独计数，主人要知道这个数。

## 出错时

| 出了什么错 | 群和来客那几轮 | 主人那几轮 |
|---|---|---|
| 插件没加载、核心没载上 | 桥按同一张表挡 | 放行 |
| 读者算不出、消息认不出 | 按最严挡 | 能确定是主人的轮才放行 |
| 开关读不出 | 线上按 `enforce` | 放行 |
| 两边判断不一致 | 按严的 | 放行，计数 |
| 判定代码自己出错 | 挡 | 放行 |

门本身不依赖证据账能不能写。

## heard 真写过以后

heard 是 dsh-fish 的「听到过」记录。把主人的话写进去，她以后能翻到；但写进事件流的删不掉。所以：

- 一旦真写过，就留一个只升不降的记号（放在证据账根里，她和帮手改不了）。
- 有这个记号以后，翻她事件流的那个工具在群、来客、维护助手那几轮一律挡，不看开关档、不看 `allowTools`、不看自动退回。
- 把 heard 改回「只数」也拿不掉这个记号：旧的照样一翻就是主人的原话。

heard 自己的开关也是失败即关，见 [ADR 0007](../adr/0007-heard-writes-fail-closed.md)。

## 以后：按受众拼请求和出口核对（P2）

门只堵得住用了工具以后的那几次请求。P2 再往前一步：

- **群和来客那一轮从空开始拼请求**：系统段、这一边能看的便条、工具表、这个聊天的近期原话、这条链上她自己压的块。拼不出来，这一轮就不发；下次主人那一轮，告诉主人哪个群有一轮没答上，不带内容。
- **一条材料能不能进**：
  - 材料的读者要盖住这一轮的每一个读者。
  - 原话按它进来时的信封算；没标签的旧材料按最严。
  - 派生物（事项卡、交接包）取所有来源读者的交集；来源不明按最严。
  - 她写的东西（块摘要、话题、用工具写下的话）按她写的时候看得到的最严算，不按它盖住的原话算。光按来源筛是不够的：「块全在群里、摘要却写了私聊」这种筛不掉。
  - 身份段里现算的几段，按读者逐次过滤；做不到就整段不给。
- **混在一起的旧块**：一块摘要里既有群里的事、也有私聊的事，不靠删。要给群看，就从群能看的原话重新写一份「受众版」，作者标成「代写」，放在旁边，原块不动。要主人批。
- **出口核对**：她往外发话，目标必须在这一轮的读者里，不在就拒。想对别的人说话，不当场发：另起一轮，按对方能看的材料重拼，她在那一轮重新写。
- **核对以出口为准**：查受众对不对，看的是压缩代理真正发给模型的那一份。
