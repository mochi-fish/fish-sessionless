# 概览

## 要解决什么

一个陪伴体要陪很久。她只有一条生活时间线，却同时面对好几种人：

- 主人：私聊，或者在桌面上直接打字。
- 群里的人：在群里 @ 她，或者回她的话。
- 来客：主人以外、来私聊她的人。
- 她自己：到点醒来、夜里想一想，这一轮只有她自己。

把这些都塞进一条会话，最省事，也最像「一个人」。但会出四个问题：

1. **群里那一轮，请求里带着私聊。** 模型每次拿到的是整条会话的历史。群里那一轮的模型，看得到主人私聊的原话。说不说出去，只看她自己。
2. **工具能翻旧事。** 她在群里一用「翻记录」「展开旧块」这类工具，私聊的内容就回到下一次请求里。
3. **压缩以后会忘，还会记错。** 历史太长要压缩。摘要写歪了、该忘的没忘、记着却想不起来、压根没记下，四种都会发生。
4. **越来越贵，最后放不下。** 历史每天都在长，每次请求都带着全部。

## 整体怎么搭

不拆会话，在旁边加东西：

| 层 | 是什么 | 谁的 |
|---|---|---|
| 原物层 | 原话、原事件、压缩块原本待的地方。只读，不改、不复制 | DSH、dsh-fish、压缩代理、聊天平台各自的 |
| 证据账 | 每条材料一行：在哪找原物、谁说的、谁能看、什么时候发生、什么时候知道的。只存编号和带盐的哈希 | 新的，和宿主无关 |
| 门 | 来话进门时认人；群和来客那几轮，工具执行前先过判定；以后请求出门前按受众拼 | 桥和 fish-ledger 插件 |
| 派生物 | 压缩块、事项卡、交接包、她写的便条 | 压缩块由她自己写；卡和交接包由规则生成 |
| 压缩代理 | 转发模型请求；她自己压缩、搜索、展开旧块；水位 | billion-context 的 fork |

所有接线都做在 DSH 插件的口子上。桥、dsh-fish、fish-ledger 是装在宿主里的插件；压缩代理是本机另一个进程。

### 组件

| 组件 | 做什么 | 哪一批 |
|---|---|---|
| `packages/config` | 共用身份配置：主人是谁、她叫什么、主人的私聊是哪个、账本根在哪。读不到就当「没有主人」，所有来话都按别人的话算 | 第一批 |
| `packages/ledger-core` | 证据账的纯 JS 核心：写行、序号、分卷、半行隔离、HMAC 和假名 | 第一批 |
| `packages/audience` | 受众的纯函数：一条消息是谁的、一轮归哪类、一个工具放不放 | 第一批 |
| `packages/fish-ledger` | DSH 插件：在宿主落盘以后记账；在工具执行前挂门 | 第一批 |
| `packages/fish-pack-zh` | 压缩代理的中文规则包 | 第一批（0.2） |
| 桥 local-bridge | 认人、打信封、送消息、请求改写、发话、门的兜底 | 第二批 |
| 压缩代理 fork | 按会话的上限、不代写、出口哈希、中文检索等 | 第三批 |

## 一轮怎么走

### 主人的私聊

1. 主人在私聊或桌面上说话。
2. 桥认出是主人，这一轮的读者是「主人和她」。证据账登记这句话（只记编号和哈希）。
3. 请求出门前，桥照现有的改写放行。主人那几轮不加新的改写。
4. 请求经压缩代理发给模型。代理在出口记一份哈希，和桥那边对账。
5. 她用工具：照旧，门不给主人那几轮加任何限制。「主人那一轮被误挡」的次数必须是 0。
6. 她回话：每一段先登记，再发，记下平台给的消息编号。

### 群里有人 @ 她

1. 群友在群里 @ 她。
2. 桥定读者：这个群的人和她。拿不到成员名单，就把整个群当成一个人。
3. 她用工具，每次都先过门。能翻到旧事的工具缺省挡住，回一句固定的照实话。表里没有的工具也挡。
4. 以后（P2）：请求出门前，桥从空开始，只用这个群能看的材料现拼一份请求，走这个群自己的受众链。拼不出来，这一轮就不发。
5. 她回话：目标必须在这一轮的读者里。回复照样落回同一份主日志。

P2 之前，群那一轮的**第一次**请求仍带着整本主册。门只堵得住用了工具以后的那几次。所以 P1 和 P2 紧挨着做。见[已知局限](known-limitations.md)。

### 来客私聊

和群一样，读者是「这位来客和她」。翻聊天记录只许翻这位来客的。来客说了跟主人有关的事，记成「待主人确认的转述」，标出是谁转的（P4）。

### 她自己醒来

读者只有她自己，全部材料她都能看，走主链。想往群里说话，以后不在这一轮直接发：另起一轮，按群能看的材料重拼，她在那一轮重新写（P2）。

## 三条不变的线

1. **她只有一份生活史。** 不按房间把她拆成几个人。不管走哪条链，回复都落回同一份主日志。
2. **主人那几轮照旧。** 门不给主人那几轮加限制；新的请求改写要她本人同意。
3. **群和来客那几轮，出错一律按「不给」。** 门所在的插件没给判定，桥按同一张表自己判；读者算不出，按最严；以后请求拼不出来，这一轮就不发。

## 分几步做

每一步单独上线、单独能退回、都能停在那里。她看得到的变化，上线前先问三件事：她知不知道，能不能反对，这是不是长在她身上的东西。

| 步 | 做什么 | 她看得到吗 |
|---|---|---|
| P0 只记账 | 证据账；代理出口记哈希；记用量 | 几乎看不到（账本目录对她关上） |
| P0.5 heard | 把主人的话洗干净记进她的「听到过」。先只数不写；门真挡以后才真写 | 真写以后看得到 |
| P1 工具的门 | 群和来客那几轮，翻旧事的工具缺省挡。先只记、再真挡 | 看得到：群里翻不到旧事 |
| P2 按受众拼请求 | 群和来客那一轮从空开始拼请求，各走各的受众链 | 看得到：群里那一轮的视图变小 |
| W 水位 | 每次请求带的历史有上限；越线只催她自己压 | 看得到：催压更勤 |
| P3 送达账 | 每段发话带纪元号；重启后按平台编号对账；查不清就记「不知道到没到」 | 很少 |
| P3.5 撤回和删除 | 撤回的消息记成「墓碑」，之后不再给 | 很少 |
| P4 事项卡 | 约定改了，追加一张卡送到当事人那一路；7 天没人提就「搁着」 | 看得到 |
| P5 换册 | 生活史太长时换一本新册，带交接包，旧册只读保留 | 看得到，要她同意 |
| P6 外部记忆库（可选） | 受众过滤做好以后，再考虑接自动回忆 | — |

先后是硬的：

- P0 打头，后面的门都靠这本账。W 例外，它不依赖证据账，可以并行。
- heard 真写必须在 P1 真挡之后：不然群里一翻，就翻出主人私聊的原话。写进去的删不掉。
- P1 和 P2 紧挨着，中间不插别的阶段。
- 回退要成对：heard 已经真写过，P1 就不能单独退。
- 换模型和改水位上限分开做。

## 设计上不做的事

- 不把她拆成每个房间一个会话。
- 不让规则或别的模型替她决定留哪些旧事、替她写摘要（她不愿意的时候）。
- 不往她的会话日志里写删不掉的元数据。
- 不在同一份请求上按读者临时删消息：删一次，缓存就整段失效。受众链从空开始、只往后追加。
- 不装第二个压缩插件和现有的并用：两个压缩写手会互相打架。
