# 证据账

证据账是一本只往后追加的账。每条材料记一行：在哪找原物、谁说的、谁转述的、谁能看、什么时候发生、什么时候知道的。

它**不存原文**。原话留在原处（DSH 会话日志、dsh-fish 事件流、压缩代理的账本、聊天平台），账里只有指针、编号、带盐的哈希、字数和计数。

为什么要它：后面的每一道门（工具的门、按受众拼请求、事项卡、换册交接）都要回答「这条材料能不能给这一轮的人看」。这个答案不能交给模型猜，要有一份机器记下的来历。为什么放在模型看不到的地方，见 [ADR 0002](../adr/0002-evidence-ledger-outside-model-view.md)。

## 三条硬约束

1. **她看到的东西不变。** 记账不加工具、不改工具说明、不改系统提示、不改请求期贴的字。唯一的变化：账本目录对她和替她办事的帮手关上。
2. **发出去的字节不变。** 往模型提供方发的正文和请求头，和不记账时逐字节相同。为了对账加的请求头只在「宿主到本机代理」这一跳出现，代理在出口剥掉。
3. **记账失败绝不影响她这一轮。** 只记不拦。写不进去就计数、退避、放回缓冲；缓冲满了先丢最不要紧的行。所有导出函数都不抛错，调用点外面再包一层保护。

## 谁来写

三个写者，各写各的子目录。一个文件只有一个写者，一个写者只有一条流、一个序号。

| 写者 | 写什么 |
|---|---|
| 桥 | 来话进门（送进她会话之前先记一行）、每次请求的清单、她每段发话的送达记录 |
| fish-ledger 插件 | 宿主落盘以后的事：她会话里的用户消息、工具结果、每轮结束时这一轮的读者、所有会话的用量；工具的门挡下的记录 |
| 压缩代理 | 每次往上游发之前，整份出站正文的哈希；提供方报的用量 |

插件只挂宿主「落盘以后才通知、监听者出错被宿主兜住」的事件口，用不着能改结果的口子。工具的门另挂工具执行前的口子，见[受众和工具的门](audience-gate.md)。

## 目录

缺省在家目录下的 `.dsh-fish-ledger/`，可以用配置或环境变量 `FISH_LEDGER_DIR`（必须是绝对路径）换。

```
<根>/
  meta.json          上线时写（宿主停着时）
  salt               上线时写一次，只有本人可读
  config.json        初值由上线脚本写，以后人改
  off                有这个文件就停写（内容不看）
  gate.json          工具的门的开关（见门那一篇）
  bridge/            桥：writer.lock、seq.json、ledger-YYYY-MM.jsonl …
  plugin/            插件：同上，另有 heartbeat.json、usage-daily.json
  proxy/             代理：同上，另有 enabled、heartbeat.json
  reports/           只有离线工具写
```

- 写者只建自己那一层子目录，从不建根。根不在就不写，每分钟再看一次。
- 分卷：每月一卷，满了接下一卷（`ledger-YYYY-MM-p002.jsonl` …）。排序按解析出的数字，不按字符串。
- 文件名里的年月按 `meta.json` 里写的时区偏移算，不按进程时区。

### 副本写不进真账

拿桥或插件的副本做测试、起副本宿主时，不能写进真的账本。所以根要同时满足几条才算「线上」：

- 没设 `FISH_LEDGER_DIR`（设了就用它，测试一律设它）；
- 加载的文件就是上线位置那一份；
- `DSH_HOME`、`DSH_FISH_HOME` 没指到别处。

代理另外要 `proxy/enabled` 存在、而且是宿主那条车道起的；在测试环境里（`node --test`）一律没有根。

## 一行记什么

| 字段 | 意思 |
|---|---|
| `schema`、`writer`、`epoch`、`lseq`、`id` | 格式版本、哪个写者、纪元、写者自己的序号、证据编号（如 `b1-1201`） |
| `kind` | 种类：原话、工具结果、门造的结果、请求清单、用量、送达、操作…… |
| `ref` | 指针：去哪找原物。通道、聊天（假名）、会话、消息编号、调用编号、平台消息编号 |
| `data` | 不是指针的事实：计数、开关、模型名 |
| `author`、`relayer` | 谁说的；经谁转的 |
| `readers`、`readersBy` | 谁能看；按什么定的（信封、按发去的聊天、按规则、归不了类按最严） |
| `occurredAt`、`learnedAt` | 事情什么时候发生的；写者什么时候记下的 |
| `derivedFrom`、`supersedes` | 从哪几条派生出来；替代了哪一条。只追加，不改旧行 |
| `status` | 每种 kind 自己的状态 |
| `hash`、`size` | 带盐的哈希；字数或字节数 |

## 读者怎么定

都是核心里的纯函数，不交给模型判。

1. **读者看聊天，作者看信封上的记号。** 主人的私聊和桌面打字：主人和她。某个群：这个群和她（群当一个整体，不记个人）。来客的私聊：这位来客和她。
2. **作者**：信封上 a 是主人；m 是这个聊天的人；x 是「主人说的话里带着别人的话」，记成混合。
3. **按规则只给她的**：宿主和 dsh-fish 自己塞进来的上下文、她自己起的轮、她定的定时提醒。
4. **从外部记忆库整理出来的东西**（开场包、回忆、记忆工具的结果）：算派生物，只进她自己的视图。
5. **归不了类的**：按最严，只给她。
6. 认不出的来源一律按最严。

信封按第一行行尾的「· 渠道:聊天）」认；消息编号按桥的格式认。

## 不存原文：哈希和假名

- 只存：编号、假名、带盐的哈希、字数、计数、模型名。
- 不存：任何正文、工具参数、工具结果、昵称、标签文字、错误文案原文、绝对路径。
- **一律用带盐的 HMAC，不用裸 sha256。** 短句（「好」「晚安」）的裸哈希能被字典撞出来，号码的裸哈希能被穷举。盐是上线时生成的 32 字节，只有本人可读。
- **号码一律换成假名**：群号、QQ 号、带号码的会话编号，都换成 `h` 加 16 位十六进制。同一个号在三个写者那里换出来的假名一样，所以连得上。
- 盐丢了，新旧哈希和新旧假名就对不上了。盐要和账一起备份，但不能放进任何仓库。

## 怎么写不坏

- **接序号不撞号**：从文件尾倒着找最后一个完整的行，再和 `seq.json` 记的下限取大；绝不从 0 起。
- **半行隔离**：上次写到一半的行（进程被杀）先隔离出去，再往后接。
- **状态文件**先写到旁边，再改名。
- **锁**：每个写者一把锁。锁丢了，缓冲里没写的行丢掉并计数，不硬写。
- **重活不在请求发出前做**：出口只做「编号、排队」，哈希在空闲时分片算，每片有时间上限，超了只记数。
- **停写**：根下放一个 `off` 文件，三个写者一分钟内停写。停记账不等于关门，门的开关是另一个文件。

## 请求清单和出口哈希怎么对账

1. 桥在每次请求出门前记一行请求清单：请求编号、哪条链、整份的哈希、和这条链上一份的共同前缀、新增消息的编号和哈希。
2. 请求编号经一个只在「宿主到本机代理」这一跳出现的请求头带到代理。代理记完出口那一行，在出口把这个头剥掉。代理没声明支持这个头时，插件那一侧不打。
3. 代理每次往上游发之前，记整份出站正文的哈希、字节数、请求编号、模型。
4. 离线工具按请求编号把两本账配起来：配不上的、哈希不一样的，都报出来。

为什么要两头都记：桥看到的不等于真正发出去的。查「受众对不对」以出口那一份为准。

## 用量

- 代理那一层记提供方报的数：总输入、缓存命中、缓存写入、输出、模型。这是最准的。
- 插件那一层记宿主看到的数，用来交叉核对。
- 插件每分钟汇总一次当天用量。缺省只记，不设上限、不填单价。
- 缓存没命中分「正常」和「异常」两本账，只记数据，分类是离线报告。

## 离线工具

对账、合并时间线、日报都是离线工具，只读、只出计数，写进 `reports/`。插件不在进程里做对账。
