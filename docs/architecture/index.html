fish-sessionless · 架构图 · 只画机制

一份生活史，每次只带眼前合适的部分

陪伴体只有一条生活时间线。旁边加一本只往后追加的证据账，记每条材料的来历和谁能看。主人那几轮照旧；群和来客那几轮，工具先过门，以后按「这一轮谁在听」现拼一份请求；出了错一律按「不给」。所有接线都做在 DSH 插件的口子上。

  • 实线框：宿主和现有插件本来就有的
  • 虚线框：方案新加的，角上写阶段号
  • 主链：主人那几轮
  • 受众链：群和来客
  • 证据账

这一页只讲机制，不讲哪一样已经部署在哪里。阶段号 P0 到 P6 是方案的先后，W 是水位那条线，见「分阶段」一节。陪伴体缺省叫「大肥鱼」，名字来自上游 dsh-fish；「主人」的具体称呼走配置。文字说明以仓库里 docs/zh/ 的中文文档为正本。

总览 两条链 工具的门 记忆和原话 水位 改约和淡忘 换册和崩溃 分阶段 借了什么 插件的极限

总览

一句话从进来到回出去，经过哪些地方

从上往下看：来话进来，过桥认人，进到她在 DSH 里的那条时间线；她每次要开口，请求先回到桥上，再经压缩代理发给模型。桥、dsh-fish、fish-ledger 是装在 DSH 宿主里的插件，图上用虚线大框圈出宿主；压缩代理是本机另一个进程。右边那本证据账一路在记。点图上方的按钮，可以只看某一种来话怎么走。

几个叫法：她在 DSH 里的那条会话叫主会话，它的记录叫主日志；会话按「册」分本，现在这一本叫主册。主人那几轮发请求走的路叫主链（带的是整本主册）；群和来客各自的路叫受众链。「信封」是桥给每条来话打的标记：哪个渠道、哪个聊天、谁说的。主人说的记 a，别人说的记 m；x 是主人说的、但这条里带着别人的话，比如主人引用了别人。

两条链

不拆她，只拆「发请求走的路」

只有一条会话时，三种来话都挤在一条链里：群那一轮的模型拿到的请求，带着主人私聊的历史。方案不把她拆成几个会话，而是让群和来客那几轮各走一条受众链：从空开始，只装这一边能看的材料。回复照样落回同一份主日志。

主链受众链
谁走这条主人、桌面、她自己醒来的那几轮每个群、每位来客各一条
里面装什么整本主册：近期原文 + 她压的块系统段、这一边能看的便条、工具表、这个聊天的近期原话、这条链上她自己压的块
不装什么不另外删她在主册写的摘要、话题、回想、写下的话；任何私聊内容
桥怎么处理照现有的改写放行；新改写要她本人同意从空开始现拼；拼不出来这一轮就不发
工具照旧，门不加限制每次过门；翻旧事只许翻这条链自己的
满了怎么办水位：催她自己压她在这条链上自己压；主链不动
出了错照旧放行按「不给」；下次主人那一轮告诉主人哪一轮没答上，不带内容
回复落在哪都落回同一份主日志

一条材料能不能进这一轮

  • 材料的读者要盖住这一轮的每一个读者。一轮里混进了不同的人，取交集，最严的说了算。
  • 原话按它进来时的信封算。没有标签的旧材料按最严，只给她。
  • 派生物（事项卡、交接包）取所有来源读者的交集；来源不明按最严。
  • 她自己写的东西（块摘要、话题、用工具写下的话）按她写的时候看得到的最严算，不按它盖住的原话算。光按来源筛不够：「块里全是群里的话，摘要却写了私聊」这种筛不掉。
  • 混在一起的旧块不靠删：要给群看，就从群能看的原话重新写一份「受众版」，作者标成代写，放在旁边，原块不动，要主人批。
  • 身份段里现算的几段按读者逐次过滤；做不到就整段不给。

工具的门 · P1

群里那一轮，她伸手翻旧事时先过一道门

请求拼得再干净，她一用工具，旧事就可能从工具结果回到下一次请求。所以群和来客那几轮，能翻到过去的工具缺省挡住，只放行逐个核过的。判定是纯函数，fish-ledger 插件挂在宿主「工具执行前」的口子上，桥在自己的检查里兜底。

群和来客那几轮：放行的

  • 发话（目标要在这一轮的读者里，P2 核对）
  • 压缩（P2 以后压的是这条链自己的）
  • 写便条（只挡「读」）
  • 逐个核过的公开内容工具
  • 外部记忆库（Mem）的工具：每一轮都放，是主人定的取舍
  • 按参数：翻聊天记录只许翻这个聊天的；读图、发图只许这个聊天里的；表情包只认图库里的

群和来客那几轮：挡住的

  • 展开旧块、搜旧块、看块列表
  • 翻她自己的事件流（记不下是哪个群、和谁）
  • 读便条、搜日记、读家目录和工作区的文件、读证据账
  • 改写文件（宿主会把说明文件读进以后的每一轮）
  • 网页搜索、网页抓取（做成开关，缺省关）
  • 帮手、定时任务这类
  • 表里没有的

挡下时回的话，大意是：「这一下在这一轮不开（这一轮不只有主人和你），没有结果给你。没拿到不等于没有，别把这一下记成『查过、没有』。」主人的称呼取自配置。不说「没找到」：门造的结果会进她的生活史，不该变成假记忆。也不指她「换个时候再用」。代价是她转述时群友会知道有这样的划分：泄的是机制，不是内容。

出了什么错群和来客那几轮主人那几轮
插件没加载桥按同一张表挡放行
读者算不出按最严挡能确定是主人的轮才放行
开关读不出线上按 enforce放行
两边判断不一致按严的放行，计数
判定代码出错挡放行
主人那一轮被误挡照挡自动把「认不清」那几种退回只记，人看过再恢复

先 audit 只记一段时间，看清群和来客那几轮本该挡几次、主人那几轮误挡是不是 0，告诉她、听她怎么说，主人看过再切 enforce。只记的时候不记正文、参数、路径、号码、群名。

记忆和原话

折掉的不等于丢掉：原话一直在，账上记着去哪找

她眼前的那份请求每一轮现拼；往下是她和规则整理出来的派生物；再往下是只存指针的证据账；最底下是原物层，永远不改、不复制。要原话，顺着指针回原处取。

她为什么会忘，这套方案各管哪一种

① 记错了
摘要写歪，和原话不一样。管法：原文留在压缩代理的账本里，搜得到、展得开；事项卡用追加的新卡取代旧说法。
② 该忘的没忘
约定早改了，旧说法还在眼前。管法：事项卡（P4）：状态变了追加一张，7 天没人提就「搁着」；撤回的用墓碑盖住（P3.5）。
③ 记着却想不起
原文在，她没想到去找。管法：提醒她可以搜；中文检索的分词和前后文；相对日期旁边注上绝对日期。
④ 压根没记下
主人在聊天软件上的话，经桥送进来，被当成插件消息丢掉，从来不进她的事件流。管法：heard（P0.5）：桥用 dsh-fish 自己的函数洗干净再写；先只数，门真挡以后才真写；开关失败即关。

证据账的一行记什么

记什么大白话
种类原话、工具结果、门造的结果、请求清单、用量、送达、操作……
去哪找原物渠道、聊天（假名）、会话、消息编号、调用编号、平台消息编号
作者和转述人谁说的；经谁转的。主人、别人、混合、宿主、她自己……
读者谁能看；按什么定的（信封、按发去的聊天、按规则、归不了类按最严）
两个时间事情什么时候发生；写者什么时候知道
来源和替代从哪几条派生出来；替代了哪一条。只追加，不改旧行
哈希和大小带盐的 HMAC，不用裸 sha256；字数或字节数。不存原文

水位 · W

每次带多少旧事去问模型：设上限，越线只催她自己压

历史每天都在长。水位给每次请求带的历史设一个上限。越线时，只在她的上下文里加中文的催压提示，不让别的模型替她写摘要；截断只是兜底，而且只认提供方报的真用量。水位做在压缩代理的 fork 里，所有新开关缺省关。

开关做什么
按会话设上限只给她的会话设一个有效上限，不跟着模型的物理窗口走；别的会话照旧
不代写越线只加催压提示；需要时先收小这一次的输出预算，不叫别的模型写摘要
截断只认真用量拿到提供方报的用量以后才截；估计的数偏大时不会误截
纪元多数守卫换模型以后旧思考块不再发、账本对不上号，被误判成「整段历史换了」而一直等确认；按多数消息判断，修掉这个误判
带图的工具结果也能折原来带图的结果钉住不折；开了以后可以折，原图在本地附件目录
图片路径占位折掉的图留一个路径占位，要看可以按路径再读
中文规则包催压的几段话和压缩、展开、搜索三个工具的说明用中文；每次请求现读

越线以后怎么走

  1. 快到上限：加一段中文催压提示，告诉她有多满、哪些块最大。
  2. 到了上限：换成紧急那一档，先收小输出预算。
  3. 她压了：自己写摘要；原文留在账本里，以后能搜、能展开。
  4. 她没压、真用量越过物理窗口：才截最老的一段，记数、查原因。

代价和要防的事

  • 缓存：每压一次，被盖住的那段缓存失效，下次重付全价。压得太勤反而更贵。
  • 回想变少：折进块里的要靠搜和展开才看得到。
  • 折错：摘要可能写歪；原文还在，但要她想得起来去搜。
  • 熔断（计划中）：同一种失败连着出现，就暂停那一类动作，等人看过再开。

换模型时的五层约定

  1. 图片：每条路由各有一次请求的图片上限；超了宿主会把最老的图永久换成占位。换之前先查上限。
  2. 用量估计：按（提供方，模型）各记一个基线和校正量，估计值不超过物理窗口。
  3. 思考块：不收别家思考块的模型，转发前剥掉；剥掉会让账本对不上号，所以配纪元多数守卫。
  4. 缓存和限流：只观察、只记数，不跟着自动调。
  5. 能用哪些模型：由一张批准过的模型表定，不在代码里写死；切之前先跑检查工具。

改约和淡忘 · P4

约好的事按原话记状态；没人提，就慢慢淡下去

「该忘的没忘」最常见的样子是：约定早改了，旧说法还在她眼前。修法不是删旧的，而是追加一张新的事项卡：状态由规则从机器事实里抽，不靠模型猜；卡只送到当事人那一路。

卡怎么来

  • 由规则从机器事实里抽：谁说的、哪条消息、什么时候。
  • 每张卡正文有字数上限。
  • 相对日期（「明天」「下周三」）写卡时换算成绝对日期，旁边留原说法。

卡送到哪

  • 只送到当事人那一路：群里约的送群，私聊约的送私聊。
  • 读者取所有来源读者的交集。
  • 来客转述跟主人有关的事：标出是谁转的，主人确认以前不当成主人说过；到主人那一轮只带这一件事，来客私聊里别的不带。

换册和崩溃 · P3 · P5

日子太长就换一本新册接着过，旧册永远留着

主会话会一直长。总有一天要换一本新册：新册带一份交接包，旧册只读保留，两本用父册编号连成一条链。换册是她看得到的大事，要她同意。

换册的步骤

  1. 只有一个负责人在换；会动「现在是哪一本」的路都算进来管住。
  2. 按规则生成交接包，给她过目。
  3. 升纪元号：旧册上迟到的写入一律挡住、记数。
  4. 新册记父册编号；旧册只读。
  5. 群和来客的受众链不走分叉，在新册里从空开始。

换模型

  • 换模型不是换册：还是同一个她、同一本册。
  • 每次换模型当成一次单独的变更：先查目标路由的图片上限、思考块的规矩，跑检查工具再切。
  • 换模型和调水位上限分开做。

崩溃和「不知道到没到」

  • 每段发话先登记再发，带纪元号；发出后记平台消息编号。
  • 重启后按平台编号对账；查不清的记成「不知道到没到」，照实告诉她，不让模型自己重发。
  • 写了一半的账行隔离；启动时对账。

上线前要过的演练

  • 在副本宿主上换一次册，再退回。
  • 换册中途杀进程，看纪元号挡不挡得住。
  • 发话中途断线，看「不知道到没到」记得对不对。
  • 请求改写被宿主封掉时，退路走不走得通。

分阶段

一层一层上；每层单独上线，都能退回，都能停在那里

先后的规矩

  • P0 打头。后面的门都靠这本账。W 例外，它不依赖证据账。
  • heard 和证据账拆成两次上线。分别归因，分别回退。
  • 真写 heard 必须在 P1 真挡之后。
  • P1 和 P2 紧挨着。P2 的副本验证和 P1 的只记观察同时做。
  • 回退要成对。heard 已经真写时，P1 不能单独退。
  • 换模型和改水位上限分开上。
  • 真要换宿主，排在 P5 之后。必须先在 DSH 里把换册跑通。
  • 每一层上线照同一个流程：等她空闲，备份，停宿主，起宿主，体检，写改动记录，告诉她。

撤回和删除：每一处能删到哪一步

在哪能不能删
DSH 会话日志、dsh-fish 事件流删不掉（只追加）。只能用墓碑盖住，之后不再给
压缩代理里的原文也许能删，要核
外部记忆库能删。自动同步开着的时候，别人的话也可能被存进去
证据账、请求记录本来就只存编号和哈希；用墓碑盖住
模型提供方、聊天对方那边删不掉
备份删了就退不回去。恢复前先取比备份新的墓碑，取不到就让恢复出来的档保持离线

借了什么

从各家项目里拿了什么、避开了什么

这套方案不是照搬或拼接哪一家插件。每个项目只取比现有做法好的纯机制，自己重写，落进已有的几个负责人（桥、fish-ledger、压缩代理的 fork、dsh-fish）。右边的标签是落在哪个阶段。只借了思路的，没有拷代码。

万卷（wanjuan）

  • 追加之前先看文件尾，隔离写了一半的行；状态文件先写临时文件再改名 P0
  • 两步做的动作记三方状态：自己的账、宿主实际、提供方用量 P0 · P3
  • 缓存没命中分「正常 / 异常」两本账（只借分类，判定自己写） P0
  • 用量估计按（提供方，模型）分桶做「加性基线 + 真用量优先」，不用纯乘性系数 W
  • 「最后一条用户消息之前字节一个不差」写成断言，就是换桥前的请求对照

dsh-live-compact

  • 派生出来的东西记着来源事件编号，原事件不动 P3–P5
  • 完成、送达只认调用编号和回执，不认「看起来发了」 P3
  • 一轮结束时收尾，下一轮开工前等它做完，有时间上限 P0
  • 已经进缓存的前缀不改，每个受众的视图只往后追加 P2

billion-context / trillion-context（保留并扩展）

  • 原文账本 + 按块还原，折叠只改发出去的视图；当她的原话层
  • 摘要由她自己写，配中文规则包
  • 系统提示保护：系统提示后面不再加系统角色的消息
  • 「只认字节一致的前缀」认会话，每个受众一条稳定的链 P2
  • 按会话上限、不代写、截断只认真用量、中文催压 W
  • 出口哈希、用量、请求编号头 P0

Comma（只借设计）

  • 来话进门就封受众标签；没标签按最严；派生物取交集；她写的按写时最严算 P0
  • 发前登记回执；不确定记「未知」、不自动重发 P3
  • 状态只在变了时追加一条带修订号的新消息，旧的不改 P4
  • 纪元栅栏：换活动册时加一，旧轮迟到的结果只记账不执行 P5

Cortico

  • 来话先落库、全局递增序号，重启后按序号补投 P0 · P5
  • 请求清单：发出去的每一段指回原事件，不往她的会话日志写 P0 · P2
  • 连续强制交接压不回去就停手、记错误 W
  • 权限收成一张表，判定和展示同一个函数，测试按表逐格生成 P1
  • 契约版本号：依赖版本对不上就整条停用并写进状态

DeepSeekBot

  • 发送的「在途」状态紧贴真正发包前那一刻落盘，区分「确定没发出」和「结果未知」 P3
  • 独立于备份之外、只追加的墓碑账，恢复旧备份前先取并集，顺着来源链连带盖住派生物 P3.5 · P4
  • 按（链、提供方、模型）被动测缓存寿命；分清瞬时忙和额度冷却 W

记忆评测榜上的几个插件

  • 无歧义的中文相对日期，按那条事件的真实时间用代码换算，旁边注上绝对日期；跳过引号、转述和假设 P2 · P4
  • 搜索剥掉信封抬头、压低高频称呼的权重、单双字 BM25、重叠窗口摘录 W
  • 事项卡到期和前置事项完成时惰性解封 P4

明确不拿的

  • 外部记忆插件整包装：单会话混流下会跨受众串台、两个写手打架，或者把唯一的时间线拆开。一律不装、不共存。
  • 图数据库和旁路小模型代写卡片：贵，会把玩笑固化成人设，还丢时序。
  • 每轮强制预塞旧话、答后二次改写：诱发背档案的腔调，篡改原话，延迟翻倍。
  • 群里自动预拉外部记忆：记忆工具已经每一轮都放，再加自动预拉，就会被动把私聊带进群那一轮。
  • 两个压缩写手并用、往她的日志里写压缩事件：删不掉，块号漂移，缓存失效。
  • 自动折、外部摘要、预压代写当日常：那样摘要就不是她写的，私聊原文还会发给别的模型。
  • 用宿主原生压缩换册、靠分叉做受众视图：前者清空状态，后者让群那一册读到私聊块。
  • 「模型看全部，只在出口管」当主防线：出口核对只是第二道。

插件的极限

每样能力用哪个口子做，墙在哪

所有接线都做在 DSH 插件的口子上（桥本身就是宿主里的一个插件），每样能力都找得到落点，没有一样非换宿主不可。最大的一堵墙是模型请求流那个口子：宿主写明只许看不许改，桥靠它默认放行，把请求改写后重发。这个口子哪天被收紧，要当成迟早的事来准备。

「稳」= 用公开的口子；「中」= 能用，但靠宿主默认放行或别人的内部函数；「弱」= 只能绕；「没核」= 可能是墙。

能力口子墙怎么绕向上游要
登记来话是谁、给谁看桥的送消息 + 会话事件。稳用户消息没有来源字段；dsh-fish 的便条、叫醒没有信封证据账在旁边另记；没信封的按最严插件追加的消息带来源和受众，并传进工具上下文
按受众拼整份请求只有模型请求流。中，最大的墙宿主写明只读，靠默认放行；改写不落日志请求清单 + 出口哈希补审计；每次升宿主前比两个版本的源码；先演练一次「改写被封」按请求的「视图投影」口子，落日志、能重放
按受众挑系统提示的段落系统提示拼装。弱系统提示会进历史；段落没有受众标记在请求视图里换内容，绝不加第二条系统消息段落带受众标记、按请求选段
查工具结果的权限工具执行前后。稳口子不知道这一轮是谁引起的插件和桥用同一个纯函数、从同一条事件流算读者；插件没留判定由桥补判工具上下文带「本轮是谁的消息引起的」
两轮之间提交在途状态一轮结束事件 + 每轮开工前。稳可能拖慢下一条回复等收尾做完再开工，有时间上限
一轮只对一个受众每轮开工前只接一部分消息。没核宿主先把整批消息领走，没接的不会自己回队自己重投；或按混进来的几个受众的交集组装开工前能把没接的消息退回去
换一本会话（换册）dsh-fish 的换会话 + 宿主建会话 + 代理接父链。中要用 dsh-fish 的内部函数，升级会断只许一个负责人；接父链的两条路先在副本上比；群和来客不走分叉dsh-fish 给一个换册服务
换模型会话级的模型选择。中窗口、分词、单价、缓存全跟着变；图片上限可能让旧图永久换成占位每次换模型当一次单独变更；切之前先查图片上限、跑检查工具
改约和淡忘不靠宿主：证据账 + 插件消息追加。稳不能用系统角色发；不能改旧消息改约记成新的一条，旧的留着便条和约定按受众查询
送达未知桥自己发话 + 回查平台消息。稳平台没有「同一条只发一次」的保证；超时可能拿不到编号照实记「不知道到没到」，不让模型自己重发
崩溃恢复一轮结束 + 开工前屏障；宿主日志只追加。中按名字停宿主停不到代理进程；代理状态只在内存写了一半的行隔离；租约；启动时对账
降低水位代理 fork 里的上下文上限。稳，是自己的代码上游不能按会话设；越线会代写摘要fork 加「按会话覆盖」和「不代写」两个开关按会话的压缩设置
受众链的缓存代理「只认字节一致的前缀」。稳桥在请求期贴的字一改，编号和块号全漂冻结请求期的字；换桥前跑请求对照

每次升级要跑的检查

  • 升宿主：按新旧版本标签比源码里用到的接口；数一遍插件提供的工具，防兼容检查悄悄跳过。
  • 升 dsh-fish：拿新包重跑桥和 heard 的测试（它们靠 dsh-fish 内部函数的形状）。
  • 换桥：同一份假历史在新旧两版上各过一遍请求改写，旧消息逐字相同。
  • 升代理：开关全关时，出站字节和上一版逐字节相同。

真撞墙时的退路

  • 请求改写被封：退到只靠工具的门 + 代理侧按受众拼。
  • 工具上下文拿不到触发者：继续用两边同一个函数从事件流算。
  • 真要换宿主：先在 DSH 里把换册跑通，再搬。

最大的风险

  • P2 之前，群那一轮的第一次请求带着整本主册。
  • 写进去的删不掉：heard、事件流、会话日志都只追加。
  • 换模型可能永久丢掉旧图。
  • 方案不新增运行时直接替换别人代码的做法；已有的几处要往宿主正式的口子上挪。
