分阶段

一层一层上；每层单独上线，都能退回，都能停在那里

每一层都写清三件事：过什么门才上、怎么退回、她那边看不看得到。她看得到的变化，上线前先问三件事：她知不知道，能不能反对，这是不是长在她身上的东西。

P0 只记账
证据账三个写者：桥记来话、请求清单、送达；插件记落盘以后的事和用量；代理记出口哈希和用量。
过门
副本宿主上跑；发出去的字节和不记账时逐字节相同；对账干净一段时间
退回
根下放 off 文件停写；或者换回不带记账的插件
她那边
几乎看不到：账本目录对她关上
P0.5 heard
主人的话洗干净写进她的「听到过」。开关失败即关。
过门
先只数；门真挡以后、主人看过只数的量点了头，才真写
退回
开关改回只数；写进去的删不掉
她那边
真写以后看得到：回想工具翻得到主人说过的话
P1 工具的门
群和来客那几轮，翻旧事的工具缺省挡。
过门
先只记一段时间；主人那几轮误挡是 0；告诉她、听她怎么说；主人看过再切真挡
退回
开关改回只记（不用重启）；heard 真写过以后不能单独退
她那边
看得到：群里翻不到旧事、看不到便条和日记
P2 按受众拼
群和来客那一轮从空开始拼请求，各走各的受众链；出口核对发话目标。
过门
副本上比「在代理侧拼」和「在桥里拼」两条路；拼出来的请求逐条核读者
退回
关掉受众链，回到只有门
她那边
看得到：群里那一轮的视图变小
W 水位
按会话设上限、不代写、截断只认真用量、中文催压、带图结果可折。
过门
上限始终高于实际体量，一档一档往下放；换模型和改上限分开上
退回
上限改回上一档；或者换回上一版代理
她那边
看得到：催压更勤，催压的话是中文
P3 送达账
发话带纪元号；重启后按平台编号核对；查不清记「不知道到没到」，不自动重发。
过门
假的聊天那头模拟「发到一半宿主退出」：重启后不重发、不误报
退回
关掉送达账的开关
P3.5 撤回和删除
撤回的消息记成墓碑：只盖住，不存原文。从旧备份恢复时，撤回的不能跟着回来。
过门
用编出来的内容演一遍「备份、撤回、从旧备份恢复」
退回
不再写墓碑；已经写的留着
P4 事项卡
约定有变时，给当事人那一路追加一张卡；取消的不再提醒，7 天没人提就搁着。
过门
用真实尺寸的系统段和完整工具表测；转述、取消、重新同意都要有对照
退回
关掉投递，同时追加一条「事项卡停用」，免得最后一张卡一直像是现行的
她那边
看得到；和她的便条对不上时以她的便条为准
P5 换册
生活史太长时换一本新册，带交接包和父链。
过门
隔离的拷贝上，轮中、发送中、换册中各强杀一次都接得上；旧引用沿父链查得回
退回
不设换册阈值；指针指回旧册
她那边
看得到，要她同意
P6 外部记忆库
受众过滤做好以后，再考虑接自动回忆。群里不开自动回忆。可选。

先后的规矩

  • P0 打头。后面的门都靠这本账。W 例外，它不依赖证据账。
  • heard 和证据账拆成两次上线。分别归因，分别回退。
  • 真写 heard 必须在 P1 真挡之后。
  • P1 和 P2 紧挨着。P2 的副本验证和 P1 的只记观察同时做。
  • 回退要成对。heard 已经真写时，P1 不能单独退。
  • 换模型和改水位上限分开上。
  • 真要换宿主，排在 P5 之后。必须先在 DSH 里把换册跑通。
  • 每一层上线照同一个流程：等她空闲，备份，停宿主，起宿主，体检，写改动记录，告诉她。

撤回和删除：每一处能删到哪一步

在哪能不能删
DSH 会话日志、dsh-fish 事件流删不掉（只追加）。只能用墓碑盖住，之后不再给
压缩代理里的原文也许能删，要核
外部记忆库能删。自动同步开着的时候，别人的话也可能被存进去
证据账、请求记录本来就只存编号和哈希；用墓碑盖住
模型提供方、聊天对方那边删不掉
备份删了就退不回去。恢复前先取比备份新的墓碑，取不到就让恢复出来的档保持离线
