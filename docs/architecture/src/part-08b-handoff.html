换册和崩溃 · P3 · P5

日子太长就换一本新册接着过，旧册永远留着

主会话会一直长。总有一天要换一本新册：新册带一份交接包，旧册只读保留，两本用父册编号连成一条链。换册是她看得到的大事，要她同意。

换册的步骤

  1. 只有一个负责人在换；会动「现在是哪一本」的路都算进来管住。
  2. 按规则生成交接包，给她过目。
  3. 升纪元号：旧册上迟到的写入一律挡住、记数。
  4. 新册记父册编号；旧册只读。
  5. 群和来客的受众链不走分叉，在新册里从空开始。

换模型

  • 换模型不是换册：还是同一个她、同一本册。
  • 每次换模型当成一次单独的变更：先查目标路由的图片上限、思考块的规矩，跑检查工具再切。
  • 换模型和调水位上限分开做。

崩溃和「不知道到没到」

  • 每段发话先登记再发，带纪元号；发出后记平台消息编号。
  • 重启后按平台编号对账；查不清的记成「不知道到没到」，照实告诉她，不让模型自己重发。
  • 写了一半的账行隔离；启动时对账。

上线前要过的演练

  • 在副本宿主上换一次册，再退回。
  • 换册中途杀进程，看纪元号挡不挡得住。
  • 发话中途断线，看「不知道到没到」记得对不对。
  • 请求改写被宿主封掉时，退路走不走得通。
