插件的极限

每样能力用哪个口子做，墙在哪

所有接线都做在 DSH 插件的口子上（桥本身就是宿主里的一个插件），每样能力都找得到落点，没有一样非换宿主不可。最大的一堵墙是模型请求流那个口子：宿主写明只许看不许改，桥靠它默认放行，把请求改写后重发。这个口子哪天被收紧，要当成迟早的事来准备。

「稳」= 用公开的口子；「中」= 能用，但靠宿主默认放行或别人的内部函数；「弱」= 只能绕；「没核」= 可能是墙。

能力口子墙怎么绕向上游要
登记来话是谁、给谁看桥的送消息 + 会话事件。稳用户消息没有来源字段；dsh-fish 的便条、叫醒没有信封证据账在旁边另记；没信封的按最严插件追加的消息带来源和受众，并传进工具上下文
按受众拼整份请求只有模型请求流。中，最大的墙宿主写明只读，靠默认放行；改写不落日志请求清单 + 出口哈希补审计；每次升宿主前比两个版本的源码；先演练一次「改写被封」按请求的「视图投影」口子，落日志、能重放
按受众挑系统提示的段落系统提示拼装。弱系统提示会进历史；段落没有受众标记在请求视图里换内容，绝不加第二条系统消息段落带受众标记、按请求选段
查工具结果的权限工具执行前后。稳口子不知道这一轮是谁引起的插件和桥用同一个纯函数、从同一条事件流算读者；插件没留判定由桥补判工具上下文带「本轮是谁的消息引起的」
两轮之间提交在途状态一轮结束事件 + 每轮开工前。稳可能拖慢下一条回复等收尾做完再开工，有时间上限
一轮只对一个受众每轮开工前只接一部分消息。没核宿主先把整批消息领走，没接的不会自己回队自己重投；或按混进来的几个受众的交集组装开工前能把没接的消息退回去
换一本会话（换册）dsh-fish 的换会话 + 宿主建会话 + 代理接父链。中要用 dsh-fish 的内部函数，升级会断只许一个负责人；接父链的两条路先在副本上比；群和来客不走分叉dsh-fish 给一个换册服务
换模型会话级的模型选择。中窗口、分词、单价、缓存全跟着变；图片上限可能让旧图永久换成占位每次换模型当一次单独变更；切之前先查图片上限、跑检查工具
改约和淡忘不靠宿主：证据账 + 插件消息追加。稳不能用系统角色发；不能改旧消息改约记成新的一条，旧的留着便条和约定按受众查询
送达未知桥自己发话 + 回查平台消息。稳平台没有「同一条只发一次」的保证；超时可能拿不到编号照实记「不知道到没到」，不让模型自己重发
崩溃恢复一轮结束 + 开工前屏障；宿主日志只追加。中按名字停宿主停不到代理进程；代理状态只在内存写了一半的行隔离；租约；启动时对账
降低水位代理 fork 里的上下文上限。稳，是自己的代码上游不能按会话设；越线会代写摘要fork 加「按会话覆盖」和「不代写」两个开关按会话的压缩设置
受众链的缓存代理「只认字节一致的前缀」。稳桥在请求期贴的字一改，编号和块号全漂冻结请求期的字；换桥前跑请求对照

每次升级要跑的检查

  • 升宿主：按新旧版本标签比源码里用到的接口；数一遍插件提供的工具，防兼容检查悄悄跳过。
  • 升 dsh-fish：拿新包重跑桥和 heard 的测试（它们靠 dsh-fish 内部函数的形状）。
  • 换桥：同一份假历史在新旧两版上各过一遍请求改写，旧消息逐字相同。
  • 升代理：开关全关时，出站字节和上一版逐字节相同。

真撞墙时的退路

  • 请求改写被封：退到只靠工具的门 + 代理侧按受众拼。
  • 工具上下文拿不到触发者：继续用两边同一个函数从事件流算。
  • 真要换宿主：先在 DSH 里把换册跑通，再搬。

最大的风险

  • P2 之前，群那一轮的第一次请求带着整本主册。
  • 写进去的删不掉：heard、事件流、会话日志都只追加。
  • 换模型可能永久丢掉旧图。
  • 方案不新增运行时直接替换别人代码的做法；已有的几处要往宿主正式的口子上挪。
