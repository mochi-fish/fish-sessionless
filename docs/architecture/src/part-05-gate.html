工具的门 · P1

群里那一轮，她伸手翻旧事时先过一道门

请求拼得再干净，她一用工具，旧事就可能从工具结果回到下一次请求。所以群和来客那几轮，能翻到过去的工具缺省挡住，只放行逐个核过的。判定是纯函数，fish-ledger 插件挂在宿主「工具执行前」的口子上，桥在自己的检查里兜底。

群和来客那几轮：放行的

  • 发话（目标要在这一轮的读者里，P2 核对）
  • 压缩（P2 以后压的是这条链自己的）
  • 写便条（只挡「读」）
  • 逐个核过的公开内容工具
  • 外部记忆库（Mem）的工具：每一轮都放，是主人定的取舍
  • 按参数：翻聊天记录只许翻这个聊天的；读图、发图只许这个聊天里的；表情包只认图库里的

群和来客那几轮：挡住的

  • 展开旧块、搜旧块、看块列表
  • 翻她自己的事件流（记不下是哪个群、和谁）
  • 读便条、搜日记、读家目录和工作区的文件、读证据账
  • 改写文件（宿主会把说明文件读进以后的每一轮）
  • 网页搜索、网页抓取（做成开关，缺省关）
  • 帮手、定时任务这类
  • 表里没有的

挡下时回的话，大意是：「这一下在这一轮不开（这一轮不只有主人和你），没有结果给你。没拿到不等于没有，别把这一下记成『查过、没有』。」主人的称呼取自配置。不说「没找到」：门造的结果会进她的生活史，不该变成假记忆。也不指她「换个时候再用」。代价是她转述时群友会知道有这样的划分：泄的是机制，不是内容。

出了什么错群和来客那几轮主人那几轮
插件没加载桥按同一张表挡放行
读者算不出按最严挡能确定是主人的轮才放行
开关读不出线上按 enforce放行
两边判断不一致按严的放行，计数
判定代码出错挡放行
主人那一轮被误挡照挡自动把「认不清」那几种退回只记，人看过再恢复

先 audit 只记一段时间，看清群和来客那几轮本该挡几次、主人那几轮误挡是不是 0，告诉她、听她怎么说，主人看过再切 enforce。只记的时候不记正文、参数、路径、号码、群名。
