# packages

这里是几个可以单独用的小包。都只用 Node 内置模块（Node 22 起），许可都是 MIT。

| 包 | 版本 | 在不在 | 做什么 |
|---|---|---|---|
| [config](config/) | 0.1.0 | 在 | 身份配置：谁是主人、主人在各渠道的号和称呼，陪伴体叫什么（缺省「大肥鱼」），可以主动开口的聊天，主会话怎么认，证据账放在哪。读不到或者写得不对，就当没有主人 |
| ledger-core | 0.1.1 | 还没放进来 | 证据账的核心：只追加的 JSONL 账本、写者锁、半行修复；号和聊天只记带密钥的假名，不存正文；判断一条消息是谁说的、谁能看 |
| audience | 1.4.0 | 还没放进来 | 这一轮在场的都有谁，以及群聊、来客那几轮哪些工具能用。纯函数，不读写盘 |
| fish-ledger | 0.2.2 | 还没放进来 | DSH 插件：从宿主的会话事件记账，并在工具调用前后按 audience 的判定把门。账本核心和 audience 从旁边的目录载入 |

## 它们怎么连

```
              身份配置（JSON，放在仓库外面）
                        │ config 读、核对、冻住
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
      桥            fish-ledger        （以后别的模块）
   bridge/         DSH 插件
        │               │
        │  audience：这一轮谁在场、哪些工具能用
        │  ledger-core：写证据账、算假名
        ▼               ▼
            证据账根目录（ledgerRoot）
```

- 桥和 fish-ledger 各自判一遍、各自记账，两边对不上时往严里错。
- 身份只有一个来源：主人的号、称呼都从 config 来，代码里不写死。
- 桥现在把 audience 整份嵌在自己的单文件里；以后改成直接用这里的包，构建时再打成单文件。

## 约定

- 读不到配置、核不过、模块版本对不上，一律往严里错：没有主人，别人的话照别人的算，门照挡。
- 测试一律用编的号（见 `tools/privacy-scan/fake-ids.json`）和编的句子；测试的临时目录或被测的模块在 `~/.dsh`、`~/.dsh-fish`、`~/.dsh-fish-ledger` 下面时直接拒跑。
- 跑某个包的测试：`node --test "packages/<包>/test/*.test.mjs"`。
