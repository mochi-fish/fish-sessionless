# 身份配置的格式（schema 1）

一份 UTF-8 的 JSON 文件，最大 64 KiB，开头的 BOM 会去掉。示例见 `example.identity.json`（全是编的）。

**规则只有一条：有一处不对，整份就不认。** 不认的时候，结果是「没有主人」：所有来话都按别人的话算，没有主动找人的聊天，没有主会话。

## 顶层

| 键 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `schema` | 是 | 数字 | 只认 `1` |
| `owner` | 是 | 对象或 `null` | 主人。写 `null` 是「这台没有主人」，不能不写 |
| `companion` | 否 | 对象 | 陪伴体。不写就是名字「大肥鱼」、没有号 |
| `proactiveChats` | 否 | 数组 | 陪伴体可以主动开口的聊天。不写就是空的 |
| `mainSession` | 否 | 对象或 `null` | 主会话怎么认。不写就是认不出，没有哪条会话算主会话 |
| `ledgerRoot` | 否 | 字符串或 `null` | 证据账的根目录。不写就是 `null`，由用它的模块按自己的缺省定 |

每一层都可以多写一个 `"$comment": "…"`（字符串），读的时候跳过。别的认不得的键都算错。

## `owner`

| 键 | 必填 | 说明 |
|---|---|---|
| `displayName` | 否 | 给陪伴体看的字里怎么称呼主人。缺省「主人」 |
| `ids` | 是 | `{ 渠道: [号, …] }`，至少一个号 |

## `companion`

| 键 | 必填 | 说明 |
|---|---|---|
| `name` | 否 | 陪伴体的名字。缺省「大肥鱼」 |
| `ids` | 否 | `{ 渠道: [号, …] }`，陪伴体自己的号（比如连接还没报上自己的号时用） |

同一个渠道里，主人和陪伴体的号不能重。

## 名字

`displayName` 和 `name`：1–32 个字，前后不能有空白；不许有控制字符、行 / 段分隔符、改变文字方向的控制符、私用区和没分配的码位。

## 号（`ids` 里的）

号一律写成**字符串**，写成数字算错。每个渠道 1–16 个号，不能重复；渠道最多 16 个。

| 渠道 | 写法 |
|---|---|
| `qq` | 5–12 位数字，不以 0 开头 |
| `bili` | 1–20 位数字，不以 0 开头 |
| `vrc` | `usr_` 加小写的 uuid |
| `mc` | 3–16 个字母、数字或下划线 |
| 别的 | 渠道名小写字母开头，只用小写字母、数字和 `-`，最长 24；号是 1–128 个可见的 ASCII 字符（没有空格） |

## `proactiveChats`

数组，最多 32 项，不能重复。每项 `{ "channel": 渠道, "chat": 聊天 }`：

- `qq`：`private:<号>` 或 `group:<号>`，号的写法同上。
- 别的渠道：1–128 个可见的 ASCII 字符。

## `mainSession`

两种写法，`by` 必须明写：

- `{ "by": "fish-home", "file": "<路径>" }`：每次现读那个 JSON 文件的 `sessionId`（dsh-fish 换会话时跟着换）。文件读不到、不是 JSON、没有 `sessionId`，就认不出。
- `{ "by": "session-id", "id": "<会话 id>" }`：写死一条会话。1–256 个可见的 ASCII 字符。

## 路径

`mainSession.file` 和 `ledgerRoot`：绝对路径，或者 `~/` 开头（展开成家目录）。相对路径不认。`\\` 和 `//` 开头的（网络路径、设备路径）也不认。

## 配置文件放在哪

`loadIdentity({ file })` 给的路径优先；没给就看环境变量 `FISH_IDENTITY_FILE`。两样都没有，就是「没有主人」（`why: "no-file"`）。没有缺省位置。

配置里有真号，放在任何仓库外面。
